# Financial Dashboard v1.0

Financial Dashboard is a free desktop application for exploring financial market data through a customizable interface. It is designed primarily for long-term analysis and educational use, with future versions planned to include portfolio analysis and management tools.

The application is built in Python with Tkinter and follows an object-oriented architecture based on reusable dashboard widgets.

> [!IMPORTANT]
> This project is not intended for real-time trading or investment execution. Data may be delayed, incomplete, or inaccurate because it is obtained from third-party services.

## Features

### Customizable dashboard layout

The application starts with a header and a single empty panel. Each panel can be:

1. Split horizontally or vertically into two resizable panels.
2. Resized by dragging the divider between adjacent panels.
3. Populated independently with one of the available widgets.

The header currently contains:

1. **Settings:** enter and store a FRED API key locally.
2. **Fullscreen:** switch between windowed and fullscreen modes.
3. **Load dashboard:** reserved for loading saved dashboard layouts in a future version.
4. **Save dashboard:** reserved for saving dashboard layouts in a future version.

The save and load controls are visible in version 1.0 but are not yet functional.

### Available widgets

#### Line Chart

Displays the price history of a selected financial instrument. The user can configure the time horizon and optionally display:

1. Trading volume.
2. A moving average with a customizable window.

#### Candlestick Chart

Displays open, high, low, and close data as a conventional candlestick chart. The user can select the instrument, observation period, interval, and time zone.

#### Term Structure

Displays the current government bond yield curve for a selected country. The user can also:

1. Add a second country as a benchmark.
2. Compare the two yield curves.
3. Display the spread between them.

U.S. Treasury data requires a valid FRED API key.

#### List Widget

Creates a user-defined watchlist of financial instruments. The user chooses both the tickers and the columns to display, including available price, performance, volume, descriptive, and risk information.

### Data export

Data generated by the widgets can be exported through the download button in CSV or Excel format.

## Data sources

The dashboard retrieves information from several external sources:

1. **Yahoo Finance**, through the `yfinance` package, for prices, volumes, instrument information, and historical market data.
2. **Federal Reserve Economic Data (FRED)** for U.S. Treasury yields.
3. **European Central Bank data services** for euro-area yield curves.
4. **World Government Bonds** for government bond yields from other supported countries.

Availability and accuracy depend on these third-party services. Market information may be delayed and should not be treated as real-time data. The application is therefore intended for research, learning, and long-term analysis rather than trading.

## Object-oriented architecture

The graphical interface is organized around a hierarchy of reusable classes.

| OOP concept             | Implementation                                                                                                           |
| ----------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Main application object | `Dashboard` manages the root window, header, panel hierarchy, settings, and widget creation.                             |
| Base class              | `DashboardWidget` extends `tk.Frame` and provides shared state-management behavior.                                      |
| Inheritance             | `LineWidget`, `TermWidget`, `CandleStickWidget`, and `ListWidget` inherit from `DashboardWidget`.                        |
| Encapsulation           | Each widget manages its own controls, state, visualization area, update logic, and export behavior.                      |
| Polymorphism            | Different widget subclasses can be created and handled through the same dashboard workflow.                              |
| Dynamic object creation | `WIDGET_CLASSES` maps widget identifiers to classes, allowing `Dashboard` to instantiate the selected widget at runtime. |
| Composition             | The dashboard contains panels, and each populated panel contains an instance of a widget class.                          |

The project also separates interface logic, data retrieval, calculations, chart construction, caching, configuration, and logging into dedicated modules.

```text
financial-dashboard-v1.0/
```

| File              | Purpose                                                                                     |
| ----------------- | ------------------------------------------------------------------------------------------- |
| `main.py`         | Creates the Tkinter root window and starts the application.                                 |
| `dashboard.py`    | Manages the main window, panels, layout controls, and widget creation.                      |
| `widget.py`       | Defines the base widget class and the four available widget subclasses.                     |
| `graph.py`        | Builds line, candlestick, term-structure, and other financial charts.                       |
| `data_loader.py`  | Retrieves market, instrument, currency, and interest-rate data.                             |
| `computations.py` | Provides performance, volatility, standardization, and related calculations.                |
| `cache.py`        | Stores selected external data and user settings locally to reduce repeated requests.        |
| `config.py`       | Contains application constants, styles, supported countries, and widget-column definitions. |
| `log.py`          | Provides timestamped logging and user-facing status messages.                               |

## Requirements

1. Python 3.10 or later.
2. An internet connection for retrieving financial data.
3. A FRED API key for U.S. Treasury term-structure data.

The graphical interface uses Tkinter, which is normally included with standard Python installations on Windows. Some Linux distributions require Tkinter to be installed separately.

## Installation

Clone the repository:

```bash
git clone https://github.com/LorenzoMuzzi/financial-dashboard-v1.0.git
cd financial-dashboard-v1.0
```

Create a virtual environment:

```bash
python -m venv .venv
```

Activate it on Windows:

```powershell
.venv\Scripts\activate
```

Activate it on macOS or Linux:

```bash
source .venv/bin/activate
```

Install the dependencies:

```bash
python -m pip install -r requirements.txt
```

## Running the dashboard

From the repository directory, run:

```bash
python main.py
```

The desktop window will open with the default empty panel. Use the central chart button to select a widget, or use the controls in the panel header to split the layout.

## FRED API configuration

To enable U.S. Treasury yield data:

1. Obtain a personal API key from the [FRED API documentation](https://fred.stlouisfed.org/docs/api/api_key.html).
2. Start the dashboard.
3. Open **Settings** from the application header.
4. Enter the key and confirm.

The key is stored only in the local cache directory. The cache is excluded from version control and should never be committed to the repository.

## Current limitations

1. Dashboard layouts cannot yet be saved or loaded.
2. Portfolio analysis and portfolio-management features are not yet implemented.
3. The application depends on the availability and format of third-party data sources.
4. Data may be delayed, missing, or inconsistent across providers.
5. The application is not designed for real-time trading.
